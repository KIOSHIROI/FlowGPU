# FlowGPU 编译器目标与验收

2026-10-15，根据用户确认的设计目标建立。本文件定义后续验收要求，不构成性能通过的证据；历史冻结协议与报告保留原结论。

## 目标

**同一份高层程序，通过通用编译优化，在一类明确的推理子图和未参与调参的形状上，取得正确、稳定、接近可靠手写基线的性能，同时减少人工干预。Graph、完整调用、编译成本和临时内存都需要分别检验。**

前端保留计算语义与必要的索引、布局和归约信息；中端选择融合、物化、重算与分块；后端及运行入口落实执行方案、缓冲区和调用契约。设备代码生成使用 Triton 等后端。收益应能从普通程序及 IR 推导，并迁移到该工作负载类的其他形状。

用户进一步明确：**生成算子的执行性能优先，编译器自身开销可以容忍。** 后续研究以 Graph 和完整调用的执行收益为主，正确性、稳定性及设备资源约束仍须满足。编译/JIT/调优耗时继续报告并注明摊销，默认不设否决候选的编译耗时上限；用户有具体部署预算时再预注册约束。已冻结实验的原门槛、失败与探索复测保留，不事后改写。

## 首个验收范围

- 先验证组合式 LSE 加权归约：覆盖不同 R/B/H/D、归约尾块和约定支持的非连续布局。dtype、数值边界、合法输入域及目标设备在具体实验中冻结。
- 保持一份参数化 DSL 源码，记录源码 SHA。允许编译器根据形状、布局和设备生成不同方案；人工按题名或确认形状添加分支须另行披露，不能计作通用自动决策。
- 手写实现在同等语义下提供独立基线。默认物化保留，重算和大 tile 显式启用；变更默认另需证据。
- gather→reduce、宽行 softmax、GEMM epilogue 可作为后续独立范围，分别建立证据，不由首个范围推断已支持或已达标。

## 必须分别记录的指标

| 维度 | 验收记录与边界 |
|---|---|
| 正确性 | 独立 Oracle；冻结 dtype、容差、特殊值、布局及输入/输出副作用；Graph 回放检查新输入，禁止缓存输出冒充计算。 |
| Graph | 固定缓冲区下的真实回放时间，声明预热、回放次数及统计口径；capture 与准备成本另记。 |
| 完整调用 | 包含该 API 所需的守卫、分配与派发；同步方式明确。批次同步后的均摊耗时与单次完成延迟分别命名，不互相替代。 |
| 编译与准备 | 分别记录前端/中端/源码生成、部署、设备 JIT、调优及 Graph capture；区分冷进程、源码/设备缓存命中、策略命中。记录调优预算和显式调用次数 N 下的摊销成本，模型结果标为模型。 |
| 临时内存 | 记录输出与 scratch 的逻辑大小、生命周期/峰值和分配次数；具备设备测量时另报 allocator 的 allocated/reserved 增量及测量方法。逻辑字节与 allocator 计数分别命名。 |
| 人工干预 | 记录人工修改 DSL、编译器和配置的次数/内容、手选 tile 或分派规则、搜索候选数和调优时间；未实测人工耗时则不报告节省比例。 |
| 决策解释 | 每个候选记录 R/B/H/D、R/D tile、grid、并行度上界、扫描次数、物化/逻辑流量及实际 registers/spill/shared；标明选择依据。逻辑流量与资源计数不能代替物理 HBM 或 occupancy 测量。 |

各实现比较时须使用一致的输入、容差、计时口径及缓冲区所有权。分配式与 caller-owned buffer API 分开对照。可执行的默认生成方案、独立手写基线及约定的 Eager/成熟编译系统基线均注明版本和覆盖范围；缺测显式记录。

## 预注册与判定

1. 冻结高层程序、父/候选编译器、harness、环境、基线、预算和协议。先用 screen 选择策略并保存哈希，再打开独立 confirmation；确认数据一经消费，后续只作诊断。
2. 在实验前确定“接近手写”的耗时比上限、逐形状最差回退、稳定性要求及内存预算。编译成本默认作为报告项，显式要求预算时另行冻结。当前尚未统一规定这些绝对验收门槛；未冻结、未测或未通过时，禁止宣称整体目标达成。
3. 现有研究的相对晋升门槛（相对父版几何平均改善至少 5%、任一确认形状回退不超过 5%）继续按各冻结协议执行。相对父版改善与接近手写是两项独立判定；Graph 和完整调用分别判定。
4. 每轮围绕一个可证伪机制开展。只调现有参数获得的收益记录为参数研究；可复用机制进入编译器后，还需父/候选对照和适当回归。记录机制是否仍为隔离原型、是否接入默认，以及需要多少人工干预。
5. 报告逐形状原始数据、汇总、失败与未测项；声明统计稳定性、设备范围和未覆盖工作负载。四类成本分别列出，不用单项改善替代整体结论。

## 当前证据与下一项假设

现有协议已覆盖独立确认、FP64 Oracle、Graph/完整调用，以及扫描、资源和部分准备/内存记录。各实验的限定范围须单独验收；更多工作负载、完整调用、跨基线成本及人工干预证据仍不足，整体目标未通过。

H100 分段统计实验 (private evidence, not included)正确性通过，性能晋升失败：确认集 Graph 存在明显逐形状回退，完整调用耗时几何平均为旧选择的 2.907 倍。局部长 R 收益保留，默认策略未改变；准备流程的改进单独报告。

后续已完成阶段ABI裁剪的独立实验；2026-10-17进一步把分段归约纳入正式compile_source、MemoryPlan、traffic和公开候选选择器。最新正式集成报告 (private evidence, not included)已在2026-10-18完整取回并审计：同一DSL、screen冻结的分段方案，在三个独立确认形状上，Graph相对物化几何耗时减少86.45%，逐形状为固定手写的1.151/1.127/1.060倍，满足本轮预注册1.20门槛。该H100 LSE子范围的Graph阶段目标通过。

该三阶段轮次的完整调用未通过稳定性判定，固定分段在较短R确认形状还存在回退。后续局部统计合并另用新协议、新确认数据验证，不能改写这个失败。

2026-10-18两阶段统计合并报告 (private evidence, not included)：同一DSL经SSA代数proof、local/merge阶段和异常条件回读，相对正式三阶段完整调用几何耗时减少8.01%，所有控制及逐形状门槛通过；Graph相对改善4.72%未达到5%，保留`primary_pass=false`。固定手写Graph耗时比1.018–1.178在本轮1.20绝对门槛内，但不能替代相对晋升。仅按完整调用收益纳入显式候选，scratch接近翻倍；较短R形状的物化完整调用仍更快。主树与冻结设备候选指纹一致，1286项CPU回归通过。

默认继续物化，重算、大tile、三阶段和两阶段显式开启。库对照、更多形状/图及原生异构设备仍缺测，整体成熟度结论不变。下一假设是把每D元素risk压缩为每local program标量，减少已测量到的scratch代价；收益未测，需另注册确认数据。本文件不启动实验、不恢复自动化。
